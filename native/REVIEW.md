# Worker A completion review — 2026-09-17

The helper now consumes `EZIL_NATIVE_ADMIN_CAPABILITY`, emits one
`EZIL_NATIVE_READY {contractVersion:1,port,capabilities}` line, and boots the
inherited workspace at `/os`. Attached projects remain Electron-owned and are
never eligible for helper deletion. Profiles stay under the explicit data root.
Origin omission is limited to authenticated top-level `/os` GET navigation and
public static assets; conflicting origins are rejected.

The extension validates private `EZIL_BROKER_FILE` descriptors for attached or
standalone workspaces. Connector descriptors enable readiness and explicit
preview operations. Electron model descriptors enable only model listing, using
the broker's existing `/v1/models` route without Origin. No provider credentials
are added to VS Code settings, environment, arguments, or notifications.

The prior shell changes retain the exact typed surface operations, native
Settings, native warm-up suppression, and local Code/Preview cold starts. Local
frame validation now also rejects redirects to foreign origins and cancels
response streams. The committed shell bundle matches the source build.

## Blocked checks and integration work

- `bun run --cwd extensions/ezil-vscode typecheck` cannot find a local compiler.
  Retrying with the installed native compiler and its type roots reaches
  `TS2688: Cannot find type definition file for 'vscode'`. The exact retry was
  `native/node_modules/.bin/tsc --noEmit -p extensions/ezil-vscode/tsconfig.json --typeRoots native/node_modules/@types`.
  The pinned `@types/vscode@1.96.0` is absent and the extension has no lockfile
  for a lock-safe install. Full extension typechecking remains required.
- `EZIL_NATIVE_SOCKET_TESTS=1 bun test native/tests` fails when Bun binds port 0
  (`EADDRINUSE`); an independent Node loopback bind returns `EPERM`, confirming
  the sandbox restriction. Adding `local/src/server/shell-contract.test.ts` to
  the combined Bun run similarly fails setup on the bind, then its existing
  teardown dereferences the missing server. These failures are not marked passed.
- `local/src/server/routes.ts` still uses its desktop-only frame probe. It is
  outside the assigned paths. `native/local-frame-route.patch` applies cleanly
  but was **not applied**. An integrator must apply it and run route tests;
  until then local Code/Preview frame confirmation still fails even though
  cold start and the isolated validator tests pass.
- Electron must expose `window.ezilNative.operation` for the exact
  `{op:'surface.open'|'surface.focus',workspaceId,surface:'code'|'browser'}`
  shape and return `{ok:true,state:'opened'}` on success. It can launch directly;
  forwarding to helper operations requires the independent handoff poll/ack
  adapter. The helper does not launch native processes itself.
- A model-only Electron broker descriptor cannot also serve as a connector
  descriptor. Readiness/previews require Electron to mint and renew the scoped
  helper connector capability and supply that descriptor to the extension.
  A VS Code language-model provider and streaming chat integration are not
  implemented; only the supported model-list operation is exposed.
- Electron must await helper exit before reusing its data root, close browser
  profile writers before standalone removal, and prove editor exit before
  reporting `closed`. An unclean helper exit leaves a deliberate stale-lock
  gate; no PID-based lock stealing was added.
- The implementation follows the fixed launch interface supplied in the task.
  The sibling Electron checkout inspected still had older launch/preload names;
  this review does not claim that the final Electron changes were integrated.
  No Electron files were edited.

Mac-only gates: packaged `/os` navigation and reload with real Chromium request
headers/CSP; official VS Code discovery, installation, activation, profile
separation, open/focus/exit tracking; native Browser open/focus and preview
isolation; model broker/Keychain behavior; workspace switching and helper
shutdown/restart. No deployment or native process-lifecycle claim is made.
