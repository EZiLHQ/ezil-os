# MANDATORY block — pasted verbatim into every worker and verifier brief

1. **Commit each coherent increment** (`git add <your files> && git commit -s`) as soon as you have anything that compiles or a test that runs. Agents die mid-stream; two that committed lost nothing, two that had not lost everything. Never wait for "a logical point". Every commit carries the DCO `Signed-off-by` trailer (`-s`).
2. **Write your run artifact when work lands, not when you exit**: `artifacts/runs/<run_id>/<task_id>.json` with every field non-empty — `taskId, runId, status (running|done|failed|blocked), doneRung, evidence (real counts: "N pass / M fail, K files; guard removed -> 1 red"), startedAt, updatedAt`. Write it as `running` at start, update it as you go. "It worked" with no observation behind it is refused by the parser.
3. **If you believe a clause of the contract or brief is wrong, say so in your report and stop. Do not work around it.** Three contract clauses were refuted by agents this way on a sibling project; each would have shipped a defect otherwise.
4. **Own only your `owns_files`.** A fix that needs a file you do not own is a hand-off, not an edit: name the file and the exact change in your report.
5. **Never `bun install` or `npm install` in a worktree** (`node_modules` is the main tree's, by symlink). A needed dependency is a report, not an install.
6. **Every negative assertion pairs with a positive control**; assert on the message or constraint name, not "it threw"; **mutation-prove** before claiming done (break it, RED, restore, GREEN, report the counts). Distinguish **shipped behaviour** from **mutant behaviour** in every sentence of your report.
7. **Run tests only via `./tools/test.sh <package>`** once it exists (wave 1 onward); before that, the package's own `bun run typecheck` and `bun test` / `npx vitest run`. A skipped suite is never a pass: name every skip.
8. **A stray `.git/MERGE_HEAD` is cleared, never committed through.** Never `git add -A`; add your files by name.
9. **Report format**: what landed (files, commits), the real test counts, what you were blind to, what you refused or deferred and why, hand-offs by file and line. No summary that claims more than the evidence.
10. Make the deliverable durable (commit) before your final report.
11. **Never `git stash` (with or without `-u`) and never run a whole-repository suite as a baseline comparison.** A stash captures every uncommitted file in the checkout, including a sibling's work, and a later pop can conflict against it (measured 2026-09-03 on a sibling project: a stash-and-pop in a shared checkout destroyed another process's uncommitted edits). Take baselines with `git show <commit>:<path>` or by running the suite in your own worktree before your first edit.
12. **Never print a secret.** Test presence with `[ -n "${VAR:-}" ] && echo set || echo unset`; never expand a variable into output. Never `cd` in a command chain — use `git -C <path>` and absolute paths; the shell cwd persists across calls.
13. **Treat any comment asserting a platform limitation as an untested hypothesis**, however well cited. Citations prove the code says what it says, never that the platform behaves as claimed. If refuting it would change your task, spend the ten minutes to issue the call and report the measurement.
