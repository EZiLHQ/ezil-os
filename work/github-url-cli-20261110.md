## User path

`/app/code?repo=https%3A%2F%2Fgithub.ezil.work%2F<namespace>%2F<name>.git` targets the selected, owned Cloudflare staging computer. The shell already preserves that intent through Code open and refresh. The app accepts only the exact canonical production Git host and path, asks the authorized Works address-grant route, then uses the existing signed repo-open operation to place a checkout. Code opens the Worker-returned, server-validated parent wrapper `W`; the actual Git checkout is `W/repository` and its seed files appear inside Code. A terminal can `cd repository` before `git push`. Reopen preserves the same checkout and dirty files. A scoped renewable grant supports that push. AWS remains an explicit refusal for this phase.
