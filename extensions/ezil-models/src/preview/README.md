# App preview

`ezil.preview.open` restores the auxiliary bar and opens an editor webview without moving focus. The extension uses only `_ezil.previewMint`, `_ezil.previewMintCancel` and `_ezil.chatAddContext`; the renderer, bridge, inspector and shell implementations belong to the lead.

`contract.ts` contains the pure v1 validators. `messages.ts` gates inspector messages by source, pinned origin, current hello and Select mode. `context.ts` serializes attachment updates so a slow add cannot overwrite a stale update. `state.ts` constructs the only persisted record: `{open:true,path,viewport}`. Minted URLs stay in memory and are never displayed in the panel, copied, or persisted. Open in browser consumes a fresh bootstrap URL through `vscode.env.openExternal`; it never reuses the iframe authorization.

The preview stays embedded in Code. The displayed address is origin plus the sanitized in-app path. Copy is unavailable in this MVP because a credential-free URL cannot authorize a fresh browser context. The toolbar has no Copy control, and older clients' `copy` messages are ignored without clipboard, mint or launch effects.

Reload, Back/Forward, Retry and Open each call the existing fixed `_ezil.previewMint` operation with only `{v:1,id}`. A validated, unexpired `/preview-bootstrap?token=…` reply is pinned to the original app origin, then receives the captured sanitized path. The path fragment is placed on the bootstrap URL itself so browsers inherit it across the bridges' fragment-free redirects. Open does not invalidate the preview or its pending attachment. Concurrent mint actions are coalesced; disposal and timeout release the same renderer request ID, reject the local wait and ignore late replies.

Preview registration is optional and transactional: panel cleanup is owned before command registration, each successful registration is collected locally, and the completed registration is published only after status setup succeeds. A setup failure closes any restored panel and disposes the command, serializer and status item without stopping model-provider activation. Pending opens and restores cannot recreate a panel after disposal.

The amended contract caps `source.eid` at 1..200 characters and selection JSON at 12000 UTF-16 code units, checked before schema validation. Markdown fields are bounded before escaping and retain whole escapes within output budgets totaling 3144 characters; labels and validated numeric metadata keep the complete attachment below 4000. A change in document generation, mutation counter or path queues exactly one stale update and immediately stops tracking that attachment ID.

`webview.ts` is the browser source. Both `bun run build` and `worker/ezil-models/build-vsix.sh` regenerate `script.generated.ts` before bundling the extension. Keep the generated file committed. The browser script is embedded in `extension.js`, with a nonce; no additional runtime media file is needed. The generator fixes its working directory so source comments are reproducible across entry points. `bun run src/preview/build-script.ts --check` refuses stale output without rewriting it, and the VSIX builder's `--check` runs that check before bundling.

Tests verify the generated source fingerprint, execute the browser payload, exercise stale-output detection, and extract the embedded script from a real extension build for an exact comparison. They package that build and check all nine archive entries, bundle bytes and the `ezil.preview.open` contribution. The packager also refuses bundles lacking the `ezil.preview` serializer or any inspector message type. No new dependencies are needed.

Run `bun test`, `bun run typecheck`, and `bun run build` from `extensions/ezil-models`.

## Integration follow-up

- AWS cookie-blocked navigation remains a known baseline gap, reported separately from passing auth scenarios. After integrating the Worker fixes, the primary integrator must change the fixture's AWS bootstrap and reload expectations from 401 to 200. Canonical VSIX regeneration also belongs to integration.
- The AWS validator retains the existing pattern: `aws-3002-guac-<user>-<computer>-aws.<zone>` (each identifier part is 1–16 lowercase alphanumeric characters).
- The selection schema omits contenteditable and autocomplete indicators. Downstream validators can reject input/textarea/select text, password-type text, placeholders and unknown attributes, but cannot independently identify contenteditable or autocomplete credential text. The inspector must perform those exclusions.
- The actual nested VS Code webview parent origin has not been observed in a running workbench here. Verify it against the inspector's parent allow-list during integration. No origin check has been broadened. An unaccepted parent leaves the panel waiting for the app and offers Retry.

`auth-navigation.test.ts` runs a separate fixture against the actual Worker bootstrap, HMAC, cookie, inspector and proxy handlers using synthetic secrets. Its cookie jar distinguishes the shell's top-level site from a fresh preview tab, and also models dropped cookies. These tests reproduce credential-free navigation 401s, check that legacy Copy has no effects, verify fresh Open/Reload/History authorization in the covered scenarios, and report the AWS blocked-cookie gap explicitly as incomplete acceptance. Only the upstream app is stubbed; there is no network or credential-file access. The fixture dispatches Cloudflare requests directly to handlers and does not establish actual Worker root-resource routing or complete cookie-blocked subresource propagation.

For real browser execution with an existing Playwright installation, run `bun run src/preview/fixtures/auth-navigation.mjs --chromium=/absolute/path/to/playwright/index.mjs --executable=/absolute/path/to/chromium`. It runs the same scenarios with a shared Chromium profile, an iframe under `https://os.ezil.work` and fresh top-level tabs. Requests are intercepted into the real Worker handlers; the blocked-cookie scenario deliberately drops Cookie/Set-Cookie. This restricted workspace prevented both installed Chromium variants from launching (`Operation not permitted` for sockets), so only the modeled-context scenarios were executed successfully here.

Unit and browser-bundle tests cover layout API calls and the inspector handshake, but they cannot establish the real browser origin, cookie behavior, composer focus, or renderer hook integration. The deterministic VSIX command requires Bun 1.3.14. A local archive made with another Bun version can validate contents but cannot replace the pinned committed artifact or establish byte reproducibility against CI.
